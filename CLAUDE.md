## Règle : préparer la migration totale à chaque changement

À CHAQUE changement qui touche la base de données ou un parcours fonctionnel, mettre à jour le paquet `supabase/migration-totale/` dans le même commit : nouvelle migration ajoutée au `manifeste.json` (`migrations`, ou `migrationsAuDeploiement` si elle renomme ou supprime ce que l'ancien code lit), puis `npm run migration:build` ; contrôle dans `verifications.sql`, entrée dans `retour-arriere.sql`, parcours dans `checklist-fonctionnelle.md`, et tout acte fait directement en production dans `journal-production.md`. `npm test` échoue si le paquet est périmé (`npm run migration:verifier`). Ne jamais appliquer en production sans l'accord explicite de l'utilisatrice (la preview et la production partagent la même base).
