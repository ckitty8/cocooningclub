## Règle : préparer la migration totale à chaque changement

À CHAQUE changement qui touche la base de données ou un parcours fonctionnel, mettre à jour le paquet `supabase/migration-totale/` dans le même commit : nouvelle migration ajoutée au `manifeste.json`, puis `npm run migration:build` ; contrôle dans `verifications.sql`, entrée dans `retour-arriere.sql`, parcours dans `checklist-fonctionnelle.md`, et tout acte fait directement en production dans `journal-production.md`. `npm test` échoue si le paquet est périmé (`npm run migration:verifier`). Ne jamais appliquer en production sans l'accord explicite de l'utilisatrice (la preview et la production partagent la même base).

## Qualité du code

- `noUnusedLocals` / `noUnusedParameters` activés : `npx tsc -p tsconfig.app.json --noEmit` doit rester à 0 erreur, `npm run lint` à 0 avertissement.
- Code mort supprimé le 16/10 (composants shadcn/ui inutilisés, anciennes pages, dépendances). Seul `src/components/ui/sonner.tsx` reste de shadcn ; ajouter un composant = l'écrire ou le réinstaller, pas réintroduire tout le kit.
- Gestionnaires de paquets : `package-lock.json` (npm, cf. README) et `bun.lock` (Bun, utilisé par Vercel) doivent rester synchronisés : `bun add/remove …` puis `npm install --package-lock-only`.
